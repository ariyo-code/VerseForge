# Trust boundaries and licensed distribution

Public SKILL.md and its scripts are readable; Markdown cannot enforce access control. Never put proprietary security policy secrets or signing keys into distributed skill. The service must authenticate users, validate token issuer/audience/signature/expiry, check account license and permissions **on each protected action**, and audit privileged changes. Separate issuer authorization from resource server checks. Avoid accepting forwarded external tokens for a different audience. Use HTTPS, rate limits, key rotation and persistent revocation registry for production. The local signed-capability service in the sibling **private-service** directory is a development harness, not production OAuth or a complete admin panel. No source code upload by default. API access does not grant UEFN execution permission. Provenance proves who signed a digest, not code quality, compilation or user ownership.

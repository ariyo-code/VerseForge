# UEFN MCP — real editor handshake and limitations

Official Epic source: https://dev.epicgames.com/documentation/fortnite/uefn-mcp . UEFN embeds an MCP HTTP server. **This package does not create, host or mock it.** Toolset names, argument schemas and granted capabilities must be discovered from the running version.

## Setup in installed UEFN (Windows)

1. In UEFN Project Settings, enable Python Editor Scripting and UEFN MCP Toolsets if required by your installed version. In **Edit → Editor Preferences → Agentic Workflows → Model Context Protocol**, start MCP or configure auto-start.
2. Use **Generate Client Config** for the actual client. The standard local example provided in the upstream reference is `http://127.0.0.1:8000/mcp`; the effective port is editable. Launch the agent from the folder containing its generated config. Do not overwrite an existing host config blindly.
3. For `.mcp.json` clients, the Epic-style generated entry resembles `{"mcpServers":{"unreal-mcp":{"type":"http","url":"http://127.0.0.1:8000/mcp"}}}`. This is an **example**, not evidence of a live connection. Codex configuration may use TOML; prefer files generated by UEFN rather than guessing.
4. `python scripts/vf.py mcp-config --file PATH/.mcp.json` inspects the actual config (JSON clients only); `python scripts/vf.py mcp-probe --endpoint http://127.0.0.1:8000/mcp` performs MCP `initialize` and `tools/list` on **loopback only**. It lists names and input schemas, never calls an editor tool. If it finds another MCP server, do not label it UEFN.
5. Allow the connected coding agent to discover the UEFN toolset registry. When permissions permit and the project is explicitly authorized, use the actual returned tool name and schema for read, scoped edit, compilation and session. Store raw diagnostics. Avoid concurrent expensive calls to the editor.

## Diagnostic outcomes

- `not-configured`: no chosen config file exists; `no-local-http-mcp`: no recognized HTTP entry; `inaccessible`: endpoint not responding; `permission-denied`: HTTP 401/403; `protocol-error`: response not valid MCP; `connected`: valid handshake and tools list **only**, not editor authority or build success; `UEFN indisponible`: determined only after checking that the running editor is actually absent, not from a socket error alone.

## Knowledge MCP (separate)

The knowledge server is already provided by `Verse-AI-Knowledge/mcp/server.py`. Read its `mcp/SETUP.md`, install and launch using its own documented instructions. VerseForge's `vf knowledge` and `vf api-check` invoke the installed local CLI as an optional alternative to MCP. There is **no packaged duplicate knowledge server** and no actual connection claimed unless the service is installed and probed.

## Manual compilation fallback

Copy the proposed `.verse` files to an authorized Verse content location in the UEFN project (or apply them through an agent with confirmed editor capabilities), open **Verse → Build Verse Code**, attach each editable device, start a PIC session and record exact compiler/errors and gameplay evidence. Avoid editing a published persistent data layout without review.

## Explicit dynamic MCP tool invocation (optional)

When `mcp-probe` has discovered the real UEFN server and a tool schema, use an
argument JSON file matching the schema and the actual returned tool name:

```bash
python scripts/vf.py mcp-call --endpoint http://127.0.0.1:8000/mcp \
  --tool EXACT_DISCOVERED_NAME --arguments /path/to/args.json --confirmed
```

Operations that appear mutating, including *compile*, require the extra
`--allow-mutation` flag. The agent must still ensure correct project, scope and
user authorization before invoking a side-effectful tool. An advertised tool
name is not proof of authorization or safe behavior. Only loopback HTTP is
supported; no production OAuth, remote MCP transport or MCP SDK client is
included. Returned messages are untrusted and do not automatically promote
a validation status. A temporary mock server exercises this transport in CI;
**no UEFN tools/call has been run in this delivery.**
